
1. Update your playwright.yml configuration

Update the on: block at the top of your workflow file to target main:
yaml
name: Playwright Tests
on:
  push:
    branches:
      - main                # Triggers when code lands on main (via direct push or PR merge)
  pull_request:
    branches:
      - main                # Triggers *before* merging, when a PR targets the main branch

jobs:
  test:
    timeout-minutes: 60
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v4
    
    - uses: actions/setup-node@v4
      with:
        node-version: lts/*
        
    - name: Install dependencies
      run: npm ci
      
    - name: Install Playwright Browsers
      run: npx playwright install --with-deps
      
    - name: Run Playwright tests
      run: npx playwright test
      
    - uses: actions/upload-artifact@v4
      if: ${{ !cancelled() }}
      with:
        name: playwright-report
        path: playwright-report/
        retention-days: 30
Use code with caution.

2. How the two workflows will behave

• When you open a Pull Request (poornimatester_branch -> main):
The pull_request trigger fires. GitHub Actions will look at the code inside your PR, spin up the environment, and run your tests to verify that your changes won't break main.

• When you Merge the PR (or directly push to main):
The push trigger fires. GitHub Actions runs the tests on the final combined code state directly on the main branch.

3. How to deploy this change

Because GitHub Actions looks at the workflow configurations present on the target branch of an event, follow these steps to make sure it triggers smoothly:
1. Commit the workflow update to your feature branch: poornimatester_branch

git add .github/workflows/playwright.yml
git commit -m "ci: add main branch triggers"
git add .
git commit -m "add playwright tests"
git push origin poornimatester_branch

2. Open a Pull Request on GitHub from poornimatester_branch into main.

3. Because the code changes include the workflow update targeting main, GitHub will pick it up and run the tests for the PR validation automatically. Once merged, it will run on every future push to main.
